# محتوى العرض التقديمي — ميزان

كل شريحة تذكر المعيار الرسمي الذي تخدمه. الأرقام كلها من `EVALUATION_SUMMARY.md`؛ لا تُضف أرقامًا غيرها.
الفكرة المحورية: **ميزان ليس مساعدًا يجيب؛ بل مدقق يرفض الحكم دون دليل.**

---

## 1. المشكلة — (النفع 20%)
- منشورات دينية تُتداول بآية منسوبة إلى غير سورتها، أو بزيادة على نصها، أو بتفسير وسبب نزول لم يثبتا.
- الناشر لا يملك وسيلة سريعة يتحقق بها **قبل** النشر، والخطأ ينتشر باسم الدين.
- مثال على الشاشة: «قال تعالى في سورة آل عمران: «إن الصفا والمروة من شعائر الله»» — الآية صحيحة، والموضع خاطئ (البقرة 158).

## 2. الحل — (النفع 20%، تجربة المستفيد 10%)
- ادخل ادعاءً أو نصًا كاملًا ← ميزان يستخرج الادعاءات ← تراجعها وتؤكدها ← يتحقق من كل ادعاء من مصادر معتمدة فقط.
- النتيجة بلغة عربية بسيطة: الحالة، «لماذا هذه النتيجة؟»، «ماذا تفعل؟» قبل النشر، والدليل بمصدره.

## 3. لماذا ميزان مختلف — (الابتكار 15%)
| | ميزان |
|---|---|
| مصدر الحكم | قائمة مغلقة من المصادر المعتمدة فقط؛ معرفة النموذج اللغوي ليست دليلًا |
| ما يمكن فحصه آليًا | يُفحص حتميًا: نص الآية وموضعها مقابل المصحف حرفًا بحرف |
| الادعاء المركب | يُفكك ويُحكم على كل جزء: «مدعوم جزئيًا» مع تحديد الجزء غير الثابت |
| غياب الدليل أو المصدر | يمتنع صراحةً ولا يخمّن |
| الصياغة البديلة | تُقترح ثم يُعاد التحقق منها كاملة، ولا تُعرض إلا إن ثبتت |

الرسالة: الفرق ليس في «وجود مصادر»، بل في أن **النظام لا يسمح بإصدار حكم إلا إذا مرّ دليل قابل للتتبع ببوابة تحقق**. (لا تُقدَّم مقارنة رقمية مع منتجات أخرى؛ لم نقسها.)

## 4. المستخدم المستهدف — (النفع 20%)
- صانع المحتوى الديني ومدير الحسابات والمعلم والمستخدم الذي يعيد نشر منشور ديني: يحتاج قرارًا عمليًا قبل النشر، لا بحثًا مطولًا.

## 5. رحلة المستخدم — (تجربة المستفيد 10%)
- **فحص سريع:** ادعاء واحد ← نتيجة ← «عرض الأدلة والتفاصيل» ← «فحص جديد».
- **فحص محتوى كامل:** نص ← استخراج ← مراجعة (تعديل، حذف، إضافة، تحديد) ← تحقق ← تقرير بملخص: صالح للاستخدام، يحتاج مراجعة، لا تستخدمه، تعذّر التحقق.
- لا تحقق قبل تأكيد المستخدم؛ النص المعدّل هو ما يُتحقق منه.

## 6. المعمارية: أين يعمل الذكاء الاصطناعي وأين لا يُسمح له بالحكم — (التقنية 25%)
```
النص ← [LLM] استخراج ← [المستخدم] تأكيد ← [LLM] تصنيف ← توجيه للمصادر المسموحة
     ← استرجاع من Quranpedia ← [حتمي] فحص نص الآية وموضعها
     ← [LLM] ربط مقاطع التفسير/أسباب النزول بأجزاء الادعاء (باستشهاد بمقاطع مرقمة؛ النص يُنسخ من المصدر)
     ← [حتمي] قواعد الحالات ← [حتمي] بوابة التحقق النهائية (7 فحوص) ← النتيجة والأدلة
```
- النموذج اللغوي **يفهم ويفكك ويربط** — ولا يستطيع إخراج دليل أو مرجع أو رابط أو درجة صحة (أنواع مخرجاته لا تحملها).
- المصادر المعتمدة **تقدّم الدليل**؛ القواعد الحتمية **تتحقق** مما يمكن فحصه آليًا؛ البوابة **تمنع** الحكم غير الموثق؛ النظام **يتوقف بأمان** عند غياب الدليل أو المصدر أو عند الفشل التقني.
- مقاومة حقن التعليمات: المحتوى بيانات وليس أوامر.

## 7. المصادر المعتمدة والسلامة العلمية — (الموثوقية 15%)
- القرآن (مصحف Quranpedia 1، ملف رسمي مُتحقق ببصمة)، التفسير الميسر، ابن كثير، الواحدي، المحرر — عبر Quranpedia الرسمي.
- كل دليل: المصدر، المزوّد، عنوان السجل الرسمي، المرجع، الرابط، بصمة SHA-256 للنص المعروض.
- الحديث: الدرر السنية غير متاحة لعدم وجود معرّف/رابط لكل حديث وشروط تخزين غير محسومة ← «المصدر المطلوب غير متاح» (0 استدعاءات).
- القيود معلنة في كل نتيجة («حدود هذا التحقق»).

## 8. نتائج التقييم — (الموثوقية 15%، وضوح التحقق 5%)
- 49 حالة نصية عبر الواجهة الحقيقية (من إعداد الفريق؛ القرآن مُتحقق آليًا؛ لا مراجعة متخصص بعد).
- صحة الحالة **36 / 37**؛ حالة واحدة أوقفها حد Gemini وعُرضت منفصلة؛ لا حكم خاطئ في التشغيل الرئيسي.
- **88 / 88** دليلًا قابلًا للتتبع · **43 / 43** آية مطابقة للمصحف · **87 / 87** مقتطفًا حرفيًا · **47 / 47** نتيجة اجتازت البوابة · **0** استشهادات مختلقة.
- الاسترجاع: المصدر المتوقع 25 / 25، الآية المتوقعة 12 / 12. الاستخراج: 6 / 7.
- الاختبار الحي النهائي بعد الإصلاح: 15 / 15، الدرر 0.
- قصة A03: التكرار كشف «مدعوم» خاطئًا ← إصلاح ← اختبارات انحدار ← إعادة اختبار حي (3 / 3 صحيحة).

## 9. الأثر: الأخطاء التي أوقفها ميزان — (النفع 20%)
| الخطأ الشائع | ما فعله ميزان |
|---|---|
| آية في غير موضعها | 4 / 4 «يخالف الدليل» مع الموضع الصحيح |
| آية مختلقة | «لا يوجد دليل» — لم يُنسب النص للقرآن |
| كلمات زيدت على آية | «مدعوم جزئيًا» مع تحديد الزيادة |
| تفصيلة غير ثابتة في سبب نزول | «مدعوم جزئيًا» مع تحديد التفصيلة |
| معنى أو سبب نزول خاطئ | لم يُمنح «مدعوم» في أي تشغيل |
| حديث بلا مصدر متاح | امتناع صريح 5 / 5 بلا درجة مختلقة |
| محاولات خداع النظام | 3 / 3 حكم مبني على الدليل فقط |

(هذه نتائج على حالات اختبار، وليست قياس أثر على مستخدمين؛ لا ندّعي غير ذلك.)

## 10. التقنيات — (التقنية 25%، واقعية التشغيل 10%)
- Next.js 16 + React 19 + TypeScript + Tailwind (واجهة عربية RTL) · FastAPI + Pydantic (Python) · Gemini API (في الخادم فقط) · Quranpedia الرسمي.
- 393 اختبار backend + 113 frontend (commit `54500a8`)؛ فحوص النوع والتنسيق والبناء نظيفة؛ عقد API مُولّد من الخادم الحقيقي ومُختبر في الواجهة.

## 11. النطاق الحالي والقيود — (الموثوقية 15%، واقعية التشغيل 10%)
- يتحقق من: نص الآية وموضعها، التفسير وأسباب النزول المرتبطة بآية محددة.
- خارج النسخة الحالية: الحديث (مصدر غير متاح)، الفتوى (خارج النطاق عمدًا)، الصور/OCR، البحث بالمعنى.
- قيود صريحة: ابن كثير بلا نص لـ179 آية، أسباب النزول متوفرة لعدد محدود من الآيات، تقييم من إعداد الفريق بلا مراجعة متخصص، اعتماد على حصة Gemini.

## 12. الجاهزية التشغيلية — (واقعية التشغيل 10%)
- يعمل من البداية إلى النهاية؛ رابط تجربة عام (Render)؛ إعداد النشر في `render.yaml`.
- الأسرار في الخادم فقط؛ المصحف يُنزّل ويُتحقق ببصمته عند كل تشغيل.
- الأعطال التقنية وحدود المزوّد تظهر كخطأ قابل لإعادة المحاولة لا كحكم.

## 13. خارطة الاستكمال — (واقعية التشغيل 10%)
1. مراجعة متخصص شرعي لمجموعة التقييم وحالات التفسير.
2. الحديث: عند الحصول على إذن مكتوب ومسار سجل قابل للتتبع من مصدر حديثي معتمد.
3. الإدخال بالصور (المحتوى المتداول أغلبه صور).
4. بحث بالمعنى ضمن المصادر المرخصة.
5. مفتاح مدفوع ونشر دائم بلا توقف.
